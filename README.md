## 2. 实践任务与测试场景 (Task Scenarios)

在近期的学习与科研中，我将上述工具深度嵌入了三类主要场景：

### 2.1 概念澄清与知识答疑

* **场景**：算法与数据结构学习。
* **实践**：在深入学习深度优先搜索（DFS）与广度优先搜索（BFS）等核心算法时，利用 ChatGPT 拆解递归回溯状态栈、分层队列遍历的底层差异，并通过动态 ASCII 图解澄清边界条件，显著降低了理论抽象门槛。

### 2.2 复杂工程与科研软件开发

* **场景**：定制化自动化工具与实验室数据流处理。
* **实践 1（轻量工具）**：基于 Kimi / DeepSeek API 编写了本地轻量级自动翻译工具，提升跨语言文献阅读速度。
* **实践 2（重度科研软件）**：针对实验室 National Instruments (NI) 采集设备的软硬件交互，让高级代码模型直接生成一套**128通道实时电信号导出、解析与解码**的专用软件，将通常需要两周的软硬件联调与工程搭建缩短至一天以内。

### 2.3 内容生成与文档打磨

* **场景**：学生工作与社会实践宣传。
* **实践**：利用大模型辅助起草、润色社会实践相关的微信公众号推文，梳理活动框架并提炼抓人眼球的排版结构。

## 3. 协作复盘：有效、无效与意外发现 (Evaluation & Reflections)

### 3.1 真正高效的地方 (What Worked)

* **工程架构与“单次通过率”极大提升**：在软硬件通讯协议、信号多线程读写等繁杂工程中，高级模型在逻辑自洽性与自纠错方面表现极为出色，几乎能做到“开箱即跑”，极大节省了繁琐的环境配置与语法排错时间。

### 3.2 表现不佳的地方 (What Failed)

* **写作“AI 味”重，缺乏灵气**：大部分模型在文案润色时倾向于堆砌生涩、生硬或别扭的书面词汇，语言缺乏温度和自然流动感，很难直接代替人工笔触。
* **长上下文记忆衰减与幻觉**：轻量级对话工具（如豆包）在多轮复杂上下文中容易丢失前置限定条件，甚至在专业技术问题上自信地编造虚假参数（Hallucination）。

### 3.3 令人意外的体验 (Surprises)

* **Agent 的主动感知与超出预期的“领域常识”补全**：在 NI 电信号采集软件开发中，我仅用自然语言明确了“导出 128 通道实时信号”的基础需求，但 AI 不仅精准构建了数据流水线，还**主动补充并配置了三种常用的信号滤波算法（高通/低通/带通）**。这种未被明确提示却极其契合工业测试实际需求的主动思考，体现了其对工程语境的深刻理解。

## 4. 未来 AI 学习工作流规划 (Future Workflow)

面对 AI 生产力带来的红利，我计划在接下来的学习和科研中构建**“AI 辅助攻坚，个人主导批判”**的工作流：

```
       [ 提出科学问题 / 设定边界 ]
                    │
                    ▼
┌──────────────────────────────────────┐
│          AI 自动化加速流程               │
│  - 论文元数据快速提取与关联分析          │
│  - 领域研究脉络与技术短板梳理            │
│  - 定制化科研工具/数据脚本快速原型开发   │
└──────────────────────────────────────┘
                    │
                    ▼
┌──────────────────────────────────────┐
│           核心个人批判流程               │
│  - 拒绝盲信“最优解”，深挖推导逻辑        │
│  - 关键经典文献亲自精读与方法验证        │
│  - 结合实验客观真实数据自主寻找创新点    │
└──────────────────────────────────────┘
```

1. **科研脉络与信息聚合加速器**：利用 AI 快速整理领域论文、追踪核心作者动态与研究演进脉络，借此快速摸清现有技术短板，寻找未被充分解决的创新切入点。
2. **定制化工具的敏捷开发者**：延续软硬件协同开发的经验，针对实验室具体实验流程开发轻量、高效的科研自动化工具。
3. **保持认知独立与批判性**：坚决避免“代码跑通即理解”的被动依赖。AI 提供的方案只是参考解，绝不能替代个人的数理推导与精细化验证；对于优质文献仍需逐字精读，在深刻理解底层机理的基础上保持独立思考。
